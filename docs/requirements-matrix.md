## Milestone gates

| Milestone | Exit criteria |
|---|---|
| 0: Repository and design baseline | Requirements traceability, initial architecture/build strategy, documented trust boundaries and risks, and the user's approved scope. Complete. |
| 1: C++ foundation and authoritative simulation | Reproducible configure/build/test commands; clean build; tests for state invariants and fixed-timestep behavior. Complete: CMake 4.4.4 configured and built with GCC 15.2.0; all 9 simulation tests passed at that milestone. |
| 2: Spatial engine | Quadtree randomized operations match a brute-force oracle; boundary cases pass; benchmark output is generated by the checked-in harness and records environment/workload. Complete: all 18 tests passed at that milestone; uniform and clustered benchmarks ran with Google Benchmark 1.9.4. Memory measurement remains deferred. |
| 3: Protocol and network hardening | Bounded versioned parsing and session lifecycle; malformed, duplicate/replay, rate, and resource-limit tests pass; transport choice and failure behavior documented. In progress: TLS 1.3 loopback integration, credential revocation/expiry checks, fixed-tick dispatch, deadlines, connection cap, replay and rate tests pass in repeated runs. One fresh Debug CTest run reported a process segfault after the TLS shutdown test printed a pass; 30 isolated CTest repeats and three full-suite repeats passed. The cause is unresolved. The optional libFuzzer target was not run because Clang is unavailable. |
| 4: Rule-based detection | Supported rule classes have tests, explainable evidence, and test-mode progressive enforcement; detector failures do not bypass authoritative validation. |
| 5: Telemetry and replay | A test session can be recorded, validated, replayed, and inspected; retention and privacy handling are documented. |
| 6: Statistical detection | Versioned features and configurable thresholds have reproducible evaluation on separate labelled traces; false-positive risks are reported. |
| 7: Synthetic data and ML | Seeded generator and leakage-aware held-out evaluation produce real metrics; model value is compared with rules; inference is omitted unless justified. |
| 8: Containers and CI security gates | Local container and CI paths are reproducible; configured checks actually execute; SBOM and signing claims match produced artifacts. |
| 9: Observability and dashboard | Metrics come from running components, avoid high-cardinality identifiers, and are viewable from documented local steps. |
| 10: Load, resilience, and security validation | Bounded adverse-load and failure tests produce recorded evidence, documented limits, and tracked remediation. |
| 11: Portfolio completion | Required diagrams, reports, operations/privacy docs, and demonstration guide match implemented behavior and can be followed from a clean clone. |

## Decisions still deferred

- Production certificate provisioning and key rotation; the TLS service uses
  caller-provided credentials and defaults to loopback.
- Adding any external library, ML model, cloud service, edge integration,
  Kubernetes, Terraform, dashboard, or persistent event broker.
- Claims of real-world cheat coverage, model accuracy, production readiness,
  security certification, or performance gains.
- A client kernel driver and collection of indefinite raw input telemetry.

Each deferred choice requires evidence and a documented decision in the
milestone that introduces it.
