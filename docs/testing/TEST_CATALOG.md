# Test catalogue

Commands assume the repository root and an existing CMake build directory.
The full CTest suite currently takes about eight seconds on the development
machine; exact runtimes vary by host.

| Suite | Purpose and location | Command and dependencies | Current result or evidence |
|---|---|---|---|
| Unit | Validate simulation, session store, protocol and Quadtree behavior in `tests/unit/`. | `ctest --test-dir build --output-on-failure`; CMake, C++20, GoogleTest. | 44 cases pass in Release. A fresh Debug run had one unresolved process crash after a test printed a pass. |
| Integration | Exercise TLS, credentials, deadlines, replay, limits and simulation dispatch in `tests/unit/network_service_test.cpp`. | Included in the CTest command; OpenSSL, Asio and loopback sockets. | 12 local TLS integration cases pass with ephemeral test certificates. One Debug process crash remains unexplained; isolated and full-suite repeats passed. |
| End-to-end | Verify a complete client-to-server-to-simulation workflow. | Current loopback TLS integration test; the broader game workflow is not yet available. | Movement reaches server state; no client state replication or match lifecycle exists. |
| Protocol conformance | Check version 1 frame boundaries and rejection cases in `tests/unit/protocol_test.cpp` and `network_service_test.cpp`. | CTest command; GoogleTest. | Valid movement, malformed input, replay and incomplete frames are tested. |
| Property and differential | Compare spatial queries with an independent map scan. | CTest command; fixed seed in `tests/unit/quadtree_test.cpp`. | 600-operation deterministic sequence; RapidCheck is not added. |
| Coverage-guided fuzz | Challenge the decoder with generated byte sequences in `tests/fuzz/protocol_fuzz.cpp`. | Configure with Clang and `-DAG_BUILD_FUZZERS=ON`; see [protocol fuzzing](PROTOCOL_FUZZING.md). | Harness added. No local run: Clang is unavailable. |
| Stateful/model-based | Compare long session and match action sequences with a reference model. | Not yet available; add with the session and detection milestones. | Deferred. |
| Mutation | Verify tests detect deliberate changes to important validation. | No mutation tool or mutation run is configured. | Deferred. |
| Security/authorization | Verify credentials, replay and bounded unauthenticated requests. | CTest command; local service only. | Network controls have integration coverage. No administrative roles or API exist. |
| Adversarial anti-cheat | Evaluate legitimate, borderline and invalid gameplay traces. | Planned with rule and statistical detection. | No detector or labeled trace corpus exists. |
| ML evaluation | Validate feature schema, leakage and model quality. | Planned with ML evaluation; no ML runtime is installed. | No model exists; no accuracy claims are made. |
| Concurrency | Check supported concurrent access and thread confinement. | CTest command; standard C++ threads. | Session-store validate/revoke stress test added. ThreadSanitizer was not run. |
| Performance and scalability | Measure spatial microbenchmarks and later service capacity. | See [performance plan](PERFORMANCE_TEST_PLAN.md); Google Benchmark for spatial work. | Spatial results are recorded. Network capacity and latency percentiles are unmeasured. |
| Soak and endurance | Detect long-run resource growth and recovery issues. | Not configured. | Deferred. |
| Fault injection and resilience | Exercise dependency, disk, network and process failures. | See [resilience plan](RESILIENCE_TEST_PLAN.md). | Network timeout and rejection cases pass. Other faults are deferred. |
| Backup and restore | Validate persisted data recovery. | No persistent store exists. | Not applicable yet. |
| Container and infrastructure | Check images, runtime configuration and IaC. | Trivy, Checkov and container tooling are unavailable locally; no deployment exists. | Deferred. |
| Supply chain | Check dependencies, secrets, provenance and CI permissions. | Planned for CI milestone. | No CI workflow or scan result exists. |
| API and dashboard | Validate HTTP contracts and authorization. | ZAP, Schemathesis and browser tests require an implemented HTTP surface. | No dashboard or HTTP API exists. |
| Accessibility | Check keyboard, screen-reader and contrast behavior. | Requires a dashboard. | Not applicable yet. |
| Regression | Preserve fixes with focused tests. | Included in CTest. | Current cases include rejection, timeout, replay and concurrency regressions. |
| Release acceptance | Verify the release checklist against actual commands and artifacts. | See [release acceptance](RELEASE_ACCEPTANCE.md). | Release gate is open. |
| Clean install and reproducibility | Configure and build from a clean checkout. | CMake configure/build/CTest commands in the README. | A fresh build passed at Milestone 3 before the latest network changes; repeat before release. |
